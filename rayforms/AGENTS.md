## Project

Ray|Forms is a React + TypeScript (Vite) forms app backed by **Project Rayfin** with Radix-based UI components styled with Tailwind CSS.
Admins create forms and share a unique link; recipients open the link and submit a response.
Auth is fully integrated: local dev uses a mock email/password flow, production uses Fabric Entra SSO.

**Anonymous data access is enabled** via the unsupported `anonymous-data-access` CLI feature flag, so
respondents can fill in a shared form without signing in. All deploys must set
`RAYFIN_FEATURE_FLAGS=anonymous-data-access` (the `rayfin:up` / `rayfin:db` npm scripts do this) or
`db apply` will fail with `AnonymousAccessBlockedError`. Import `@anonymous()` from
`@microsoft/rayfin-core`. See "Security model" in `README.md` before changing permissions.

## Architecture

### Service Layer

- **ServiceContainer**: Singleton that initializes and provides access to services; auto-detects local vs. production and selects the appropriate auth service
- **RayfinClientService**: Manages the RayfinClient singleton instance
- **RayfinFormService**: Form and question CRUD via DataApi fluent interface
- **RayfinResponseService**: Submission and answer reads/writes

### Auth Service Layer

- **RayfinAuthService**: Fabric Entra authentication operations (production)
- **RayfinFabricAuthService**: Delegates to `@microsoft/rayfin-auth-provider-fabric` SDK for Entra flows
- **MockAuthService**: Local development mock authentication (email/password via local backend)
- **AuthContext**: React context for auth state management

### Routing

- `/auth` – Public auth page (Fabric sign-in or mock sign-in; redirects onward if authenticated)
- `/auth/callback` – Fabric Entra OAuth callback
- `/` – Protected dashboard listing the signed-in user's forms
- `/forms/new`, `/forms/:id/edit` – Protected form builder
- `/forms/:id/results` – Protected responses table (owner-only by policy)
- `/f/:token` – Share link. **Public**: no auth guard, respondents need not sign in.
  Anonymous callers cannot read back rows they write, so `RayfinResponseService` generates IDs
  client-side and tolerates that specific DAB error.

### Key files

- `rayfin/data/Form.ts` – Form entity: share token, open/closed state, owner policies
- `rayfin/data/FormField.ts` – Questions (`kind`, JSON-encoded `choices`, `position`)
- `rayfin/data/FormResponse.ts` / `rayfin/data/Answer.ts` – Submissions and their answers
- `src/services/ServiceContainer.ts` – Service initialization with auth-mode detection
- `src/hooks/useForms.ts` – Form list and lifecycle operations
- `src/pages/FormEditor.tsx` – Form builder (create and edit)
- `src/pages/PublicForm.tsx` – Share-link form renderer and submit

## Code conventions

- TypeScript strict mode; prefer small functional React components.
- Keep UI logic in `src/`; keep data model code in `rayfin/data/`.
- Services follow the singleton pattern via `ServiceContainer`.
- `ServiceContainer` auto-selects `MockAuthService` for localhost backends and `RayfinAuthService` for production.
- Always set `max` on `@text()` — unbounded `NVARCHAR(MAX)` breaks GraphQL schema generation on MSSQL.
- Policies cannot traverse relationships, so `owner_id` and `isClosed` are denormalized onto child entities.
  `setFormClosed` must keep `FormField.isClosed` in sync.
- The policy DSL only exposes the `sub`, `email`, and `role` claims with `eq`/`ne`/`and`/`or`.
- Every entity action must carry a policy. `create` policies bind `owner_id`/`respondent_id` to `claims.sub`
  so callers cannot forge ownership.
- `findById` selects only the primary key in this SDK version — use
  `.select([...]).where({ id: { eq: id } })` instead.
- Never hard-delete a `FormField` during an edit: `Answer.field_id` is a foreign key. Set `isDeleted`.
- Delete children before parents (answers -> responses -> questions -> form).

## Design system

A clean, professional light theme aligned with the root `DESIGN.md`. White surfaces sit on a soft
grey canvas, with Ray|Works navy (`#0B2A5B`) and blue (`#2F80FF`) as the brand anchors. IBM Plex
Sans is used throughout; IBM Plex Mono is reserved for tabular figures. Tokens live in
`src/styles/design.css`.

- Use `src/assets/rayforms.svg` for product branding; do not reconstruct the wordmark with text or
  pair it with Ray|Works. Keep standard header logos at 32px desktop and 28px mobile.
- Use the semantic tokens (`--surface`, `--text`, `--text-muted`, `--border-subtle`, `--brand`)
  and the `.card` / `.card-interactive` / `.font-heading` / `.font-data` / `.label-caps` /
  `.fade-in` primitives. Prefer shadcn utilities (`bg-card`, `text-muted-foreground`) where they
  already map.
- Tokens are declared on `:root:root`, not `:root`. `theme.css` declares the same shadcn token
  names and is emitted later in the bundle, so a plain `:root` loses the cascade and the stock
  palette silently wins. Keep the doubled selector.
- Keep body text at 14px+ and small caps labels at 12px with modest tracking; the previous
  10px/0.18em labels were not readable.
- Charts live inside grid cells, so their containers need `min-w-0`: grid items default to
  `min-width:auto` and refuse to shrink, which causes horizontal overflow.
- Keep the results route lazy-loaded — recharts nearly doubles the bundle and only that page
  needs it.
